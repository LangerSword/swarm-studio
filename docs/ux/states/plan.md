# State table: a game plan and its sketch sheets

A game plan is one JSON file (`<data>/plans/<id>.json`, `engine/plan.mjs:311`) plus the game chat that points at it (`chat.plan`, `engine/chats.mjs:25`). The plan file holds the cards, the gate, the sketch sheets, the other pictures and the art build. The chat holds its own lock (`chat.state`), a "changed since the plan was made" flag (`chat.stale`) and the sheets the person skipped (`chat.skip`). This table lists every state those fields can make, what each surface shows in it, and where surfaces disagree. One finding sets the frame: "Build" on a plan means painting its pictures and making its 3D models (`server/plans.mjs:74`). Nothing in the code builds the game from a plan: `plan.build.run` is read (`web/kit-game.js:53`, `engine/chats.mjs:206`) and never written, and `GET /api/plans/:id/brief` (`server/plans.mjs:298`) has no caller in `web/` or `ui/src` (grep). So "building from the locked plan" and "built" are not states of a plan today. Per-picture detail (one picture painting, failing, being drawn again) belongs in `picture.md`; here the sheets appear only as they move the plan.

## States

Each state is defined by data. "Plan" means the plan file, "chat" the game chat's `chat.json`.

**The plan and its gate**

| id | State | The data that makes it so |
|---|---|---|
| S1 | Draft, questions open (needs you) | The chat exists with `plan: null` (`engine/chats.mjs:25`) and `openQuestions` is not empty (`engine/talkplan.mjs:211`). The board is in draft mode (`web/plan.js:440`) and shows a throwaway plan made from the chat on each turn (`server/talk.mjs:39`). No plan file. |
| S2 | Draft, written, waiting on Lock (needs you) | Same, but no question is open, so the turn writes `chat.spec` and offers Lock (`engine/talkplan.mjs:407`, `engine/talkplan.mjs:412`). No plan file yet. |
| S3 | Plan made, not locked (needs you: the gate) | The plan file exists (`engine/plan.mjs:329`) with `gate.locked: false`, `gate.phase: null` (`engine/plan.mjs:101`). Made by the chat's Lock (`server/talk.mjs:76`), by `POST /api/plans` (`server/plans.mjs:270`) or by a template remix (`server/plans.mjs:177`). |
| S4 | Locked, everything | `gate.locked: true`, `gate.phase: 'all'`, with the price and time (`engine/plan.mjs:281`). |
| S5 | Locked, test one first | `gate.locked: true`, `gate.phase: 'first'` (`engine/plan.mjs:281`). Only the board's gate can set it (`web/plan.js:387`); the chat's Lock never sends `testFirst` (`server/talk.mjs:85`). |
| S6 | Tested: the first piece is made, the gate is open again (needs you) | `gate.locked: false` with `gate.tested: <name>` (`server/plans.mjs:86` for 2D, `server/plans.mjs:127` for 3D). |
| S7 | Reopened: a locked plan was edited (needs you) | `gate.locked: false`, `gate.reopened: true` (`engine/plan.mjs:232`), set by any card, systems or starter edit (`engine/plan.mjs:211`, `engine/plan.mjs:217`, `engine/plan.mjs:229`). No surface reads `reopened` (grep: written once, read nowhere). |
| S8 | Stale: the chat decided something new after the plan was made (unsure) | `chat.stale: true` (`engine/talkplan.mjs:363`), and `chat.state` back to `'open'` (`engine/talkplan.mjs:362`). | S9 | Re-planned: the same id, a fresh shape, old pictures dropped | `plan.replanned: { at, note, was }` (`engine/plan.mjs:186`); every other field replaced (`engine/plan.mjs:185`). **The art build (the board's "Build")**

| id | State | The data that makes it so |
|---|---|---|
| S10 | Building (working) | `build.state: 'building'` (`server/plans.mjs:338`) and the plan id in the server's in-memory set (`server/plans.mjs:76`). | S11 | Build stuck (failed, unsaid) | `build.state: 'building'` on disk with no build running. | S12 | Build ended with failed pieces (partly done) | `build.state: 'idle'` and a character with `state: 'failed'` (`server/plans.mjs:95`, `server/plans.mjs:102`, `server/plans.mjs:119`), a model with `error: 'no Meshy key'` (`server/plans.mjs:103`), or a sprite with `state: 'failed'` and a raw `error` (`server/plans.mjs:45`). |
| S13 | Every picture painted (done) | No field. Derived: sheets picked or skipped, pieces, mocks and backdrops all done, so `nextStep` returns `done: true` (`engine/gamestep.mjs:130`). |
| S14 | Game built from the plan | No data. See the intro. A game project that exists is a run with its own spec; the plan is tied to it only by a title match on Projects (`web/home.js:86`). |

## The table

Two tables, the same rows. "Step line" is `nextStep(...).text` (`engine/gamestep.mjs:85`). The board gets it as `plan.next`, made with an empty chat and no environment (`server/plans.mjs:32`); the chat gets it with the chat and the environment (`server/talk.mjs:164`, `engine/talkplan.mjs:376`). The `gc-*` walkthrough steps (`scripts/walkthrough-chat.mjs:54`) are not in the screenshot digest, so chat cells rest on code and tests, not on a picture.
