# State table: one turn of the planner chat

One turn is: the person sends a message (or presses a button under Hermia's last message), and Hermia, the planner, answers or acts. This file covers the turn in the website chat, the app chat and the game chat of the classic front end (`web/`). A turn has no single record today. It takes one of seven roads, and each road keeps its own state: the website and app talk (`POST /api/discuss`, the conversation held in the browser at `web/canvas/talk.js:21`), the saved talk (`POST /api/talk`, the turn written by `server/talk.mjs:46` or `server/talk.mjs:146`), Ask mode (`web/chatmode.js:196`, nothing saved), Fix mode (`web/chatmode.js:213`), the App room (`web/canvas/rooms.js:774`), a build started straight from the box (`web/canvas/loop.js:482`), and the Overview's bar (`web/project.js:1327`). Which road a message takes is decided by `web/chatmode.js:41` and by the order of the checks in `web/canvas/loop.js:414`. The game PLAN's own states are in `plan.md` and a build's states are in `build.md`: a turn that starts a build is followed here only to the hand-off.

## The table

Two tables per chat, same rows. Table 1 is the chat itself. Table 2 is everything around it. "nothing" means the surface shows no sign of the state.

The App room and the Game room have no chat box of their own: both use the chat's one box (`#brief`) and only change its placeholder (`web/canvas/rooms.js:70`, `web/canvas/rooms.js:413`). The other inputs in `web/canvas/rooms.js` are not chat turns: "Or in your own words" (`web/canvas/rooms.js:1054`) answers a question card of the app build, and the Game room's idea and own-words inputs (`web/canvas/rooms.js:1264`) belong to its question steps. Where those send is UNCHECKED here (`build.md`). `web/chatter.js` is sound only and shows no state.

## Where the state should live

What a website's or an app's chat may say about its build now has one reader: `engine/chatstep.mjs` (`chatFacts` from `engine/buildstate.mjs` and the app's state object, `stateLine`, `nextStep`, `checkSaid`), used by `/api/discuss` (the talk and Ask mode), `/api/discuss/step` and `/api/talk` (`server/server.mjs` `chatTruth`); the game chat's is `engine/gamestep.mjs`, and both cut false sentences with `engine/claims.mjs`. An app's facts take any state object with `{ state, hasApp, steps }`, so a state function for apps plugs in. The turn itself still has no selector:

There is no selector for a turn today. The nearest things are the saved planner turn in the chat file (`engine/chats.mjs:108`: its `options`, `cards`, and for a game `step`, `wait`, `sheet`, `price`), `pendingAsk` for the website's open question (`engine/askfirst.mjs:88`), and the game's `step` that `GET /api/talk/:id` adds from the plan file (`server/talk.mjs:196`). One function should sit beside them, for example `turnState(chat)` in `engine/chats.mjs`, returning one of: idle, thinking, answered, needs you (question, brief, cards), acted, waiting, nothing happened (why, next), no answer (why, try again), no model, no Hermes (set up), handed to a build (run). Every road should write the turn first and its outcome after, failures included, so the state survives a reload. Surfaces that do not read any such state today: the website and app talk, which keeps the conversation in the browser and posts it whole (`web/canvas/talk.js:80`); Ask and Fix (`web/chatmode.js:201`, `web/chatmode.js:216`); the App room's `appAsk` (`web/canvas/rooms.js:787`); the Overview's bar, which decides from `board.app` (`web/project.js:1337`); both Chats lists, which read only `state` (`web/home.js:275`, `web/canvas/talk.js:346`); and the React hook, which copies the classic talk (`ui/src/chat/useTalk.ts:100`). C2, C3 and C21 share one root that belongs in the same place: "this project is an app that is not built yet" is not a state any road reads, so an unbuilt app is treated as a website.
