# State table: one picture being painted

One picture is one slot that an image model is asked to fill: a website's art slot (`<img data-gen>`), a sketch
sheet or mock on a game's Plan board, one piece of a game build's art, an option in the game workshop, a still
for a film. There is no single "picture" object in the code. A website slot's state is folded from four events
(`image:queued`, `image:sent-back`, `image`, `image:failed`) by four different readers; a Plan board picture is a
`state` field on the plan; a game build's art is live `art:job` events plus files on disk plus the words of step
lines. This file lists the states the data can reach, what each surface shows in each, and the holes. Classic
`web/` front end only; `ui/src` gets one line at the end.

## States

Ids are shared by all kinds. "A" is a website's art slot, "B" a Plan board picture, "C" a game build's art.

## Where the state should live

There is no single reader today. The closest is the slot fold in `runBoard` (`server/board.mjs:58` to `:71`): one
record per slot with `state` (painting, again, failed, done), `message`, `problems`, `from`. It should become the
one selector, say `pictureSlots(events, { paint, choice })`, and gain what it lacks: "not asked" for slots found in
the sections' HTML with no event, "stopped" apart from "failed", a time limit that turns a slot left painting into
"unsure", the kept older picture when a repaint fails, and "no image model". Surfaces that do not use it today:
the deck slot and its tag (`web/canvas/marks.js:228`, own map `S.images` with `undefined` and `''`), the carried
card (`web/canvas/carry.js`, live events only), the Design panel (`web/canvas/start.js:339`, `pics.pending` and
`a.painting`), the chat lines (`web/canvas/events.js:251`, `:254`), the asset pane (`engine/assets.mjs:43`), the
doctor (`engine/doctor.mjs:48`) and Setup (`engine/setup.mjs:19`). Plan pictures already have one record each
(`settleStale` then `planView`, `server/plans.mjs:33`), read by the board alone. A game's art has none: it should
be a kept record per art item (state, reason, source: painted, library, drawn in code) written by `paintGame`,
read by the wall, the Art sheet, the Overview and Projects in place of `art:job` memory, file names and step-line
regexes.
